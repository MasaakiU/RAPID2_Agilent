# `.rpd.csv` フォーマット仕様（ターゲットと定量値）

Targets パネルの「…」メニュー（Import targets… / Export targets…）と、File メニューの Export Targets / Load Targets が読み書きするファイルの仕様。
1つのファイルが、**面積などの定量表**と、**ターゲットの使い回し**の両方を兼ねる。RAPID2 の Export Targets / Load Targets の考え方を引き継ぎ、RAPID2 が書き出した古いファイルも読める（後方互換）。

状態：Export、Import とも実装済み（`services/rpd_csv.py`、`services/quantification.py`、`io/run_hashes.py`。Import の画面は `MainPresenter.load_targets_clicked`）。§8 の未決事項は Import の実装で決めた。

## 1. ファイル

| 項目 | 仕様 |
| --- | --- |
| 拡張子 | `.rpd.csv`。保存ダイアログが二重拡張子を落とすことがあるので、保存後にコード側で揃える（`foo`、`foo.csv` → `foo.rpd.csv`） |
| 文字コード | UTF-8 のみ。書き出しは BOM 付き（Excel で µ や日本語を正しく表示させるため）。読み込みは BOM の有無を問わない |
| 区切り | タブのみ。引用符は使わない |
| 改行 | 書き出しは LF。読み込みは LF と CRLF |
| 1行目 | 見出し行 |

- 中身はタブ区切りで、拡張子だけ `.csv`（RAPID2 と同じ。化合物名にカンマが多いため、カンマ区切りにはしない）。
- 名前（`compound_name`）と Note（`note`）には、タブと改行を入れられないようにする。パネルの入力欄と表のセルでは、打ったり貼り付けたりしたタブ・改行を、その場でスペースに置き換える（エラーにはしない）。Target もタブ・改行を含む名前と Note を受け付けない。
- Import のファイル選択では `*.rpd.csv` と、古い RAPID2 用に `*.csv` を選べる。**新旧の判定は拡張子ではなく見出し行で行う**（§5）。
- Excel で編集・保存したファイルを読むことは想定しない。

## 2. 行の構成

- **1行 = ターゲット × データファイル。** 並びはターゲットの番号順で、その中はデータファイルの表示順。
- データファイルを1つも開いていないときは、ターゲット1件につき1行を書き、ファイル列と結果列は空にする。

例（ターゲット2件、ファイル3つ → 6行。一部の列のみ）：

| # | compound_name | RT | file_name | area |
| --- | --- | --- | --- | --- |
| 1 | choline | 3.40 | A.d | … |
| 1 | choline | 3.40 | B.d | … |
| 1 | choline | 3.40 | C.d | … |
| 2 | choline-d9 | 3.65 | A.d | … |
| 2 | choline-d9 | 3.65 | B.d | … |
| 2 | choline-d9 | 3.65 | C.d | … |

## 3. 列

列名は RAPID2 にそろえる。**意味が同じ列は RAPID2 と同じ名前、意味が違う列と新しい項目は新しい名前**にする（例外は `formula` だけ）。書き出しは下の順。

### 3.1 ターゲット列（Import で読む。すべて必須）

| 列 | 中身 | 空欄 | RAPID2 との関係 |
| --- | --- | --- | --- |
| `#` | ターゲット番号（正の整数）。同じターゲットの行は同じ値 | 不可 | RAPID2 では見出しのない行番号だった位置 |
| `compound_name` | 名前 | 可 | 同じ |
| `formula` | **中性分子**の組成式（このアプリの書式。同位体 `[13C]`、括弧のグループ可） | 可 | ⚠ RAPID2 では電荷付きのイオン式（`C5H14NO+`）。名前が同じで中身が違う唯一の列 |
| `adduct` | `[M+H]+` など（このアプリの adduct 書式） | 不可 | 新規 |
| `trace_type` | `XIC` / `TIC` / `BPC` | 不可 | `is_TIC` の代わり（BPC を表せないため） |
| `MS_level` | `All` / `MS1` / `MS2` | 不可 | 新規 |
| `precursor_m/z` | MS2 のプリカーサー m/z | MS2 以外は空欄 | 新規 |
| `collision_energy` | MS2 の CE | MS2 以外は空欄 | 新規 |
| `isolation_width` | MS2 のアイソレーション幅 | MS2 以外は空欄 | 新規 |
| `m/z` | 中心 m/z（MS2 ではプロダクトイオン） | TIC/BPC は空欄 | 同じ（RAPID2 は TIC で -1） |
| `m/z_range` | m/z の ±幅（単位は `m/z_range_unit`） | TIC/BPC は空欄 | 同じ（RAPID2 は常に絶対値） |
| `m/z_range_unit` | `abs` / `ppm` | TIC/BPC は空欄 | 新規 |
| `RT` | 中心 RT [min] | 不可 | 同じ |
| `RT_range` | RT の ±幅 [min] | 不可 | 同じ |
| `note` | Note | 可 | 新規（列の末尾に置く） |

- MS2 でも `precursor_m/z` などは空欄でよい（Target がそれを許すため）。
- `ppm` の幅は整数（m/z コントロールが整数のスピンボックスのため）。
- TIC/BPC の行の m/z の3列は、Import では空欄なら画面の初期の m/z 窓（150.5 ± 0.05、abs）にする（Target は m/z を持つため）。TIC/BPC のターゲットの m/z は書き出さないので、往復では残らない。

### 3.2 ファイル列・窓の列・結果列（書き出しのみ。Import では読み飛ばす）

| 列 | 中身 | RAPID2 との関係 |
| --- | --- | --- |
| `file_path` | データファイルのパス | 同じ |
| `file_name` | データファイルの名前 | 同じ |
| `data_hash` | データの SHA-256（§3.3）。同一のデータかの最終確認に使う | 同じ名前・同じ役割。値の互換はない（RAPID2 は .rpd から計算） |
| `scan_sha256` | スキャン表の SHA-256（§3.3）。元のファイルの候補を探す鍵 | 新規 |
| `scan_settings` | その行の計算に使ったスキャンの、イオン化法・極性・スキャンの種類（例：`ESI+ Scan`、`ESI- ProductIon`）。§3.4 | 同じ（RAPID2 は `ESI+ QuadrupoleTimeOfFlight SCAN` など） |
| `m/z_btm`, `m/z_top` | 実際に使う m/z 窓。ppm も m/z に換算。TIC/BPC は空欄 | 同じ（RAPID2 は TIC で 0 / inf） |
| `RT_btm`, `RT_top` | ターゲットの RT 窓。ファイルごとの積分区間（§6.1）があるときは、ピークを探す範囲 | 同じ |
| `RT_btm (value used for calculation)`, `RT_top (value used for calculation)` | 計算に使った最初と最後のスキャンの RT | 同じ。RAPID2 では同じ列が2回出ていたが、1回だけにする |
| `N_scans (value used for calculation)` | 計算に使ったスキャンの数（欠測を除く。§6.2） | 新規。欠測を飛ばして積分するので、面積がいくつのスキャンから出たかを表で分かるようにする |
| `area`, `area (baseline adjusted)`, `height`, `baseline_height`, `RT peaktop`, `mz peaktop` | 定量値（§6） | 同じ。定義も同じ |
| `area (deconvolved)`, `area (deconvolved) sigma`, `area (deconvolved) 95% interval` | ピーク検出器が分けたピークの形の面積と、その不確かさ（§6.3） | 新規 |

書き出しの列順：`#`, `compound_name`, `formula`, `adduct`, `file_path`, `file_name`, `data_hash`, `scan_sha256`, `scan_settings`, `trace_type`, `MS_level`, `precursor_m/z`, `collision_energy`, `isolation_width`, `m/z`, `m/z_range`, `m/z_range_unit`, `RT`, `RT_range`, `m/z_btm`, `m/z_top`, `RT_btm`, `RT_top`, `RT_btm (value used for calculation)`, `RT_top (value used for calculation)`, `N_scans (value used for calculation)`, `area`, `area (baseline adjusted)`, `area (deconvolved)`, `area (deconvolved) sigma`, `area (deconvolved) 95% interval`, `height`, `baseline_height`, `RT peaktop`, `mz peaktop`, `note`

RAPID2 の列のうち出さないもの：`is_TIC`（`trace_type` に置き換え）、`view_range_s_x` / `view_range_c_x`（このアプリにはターゲットごとの表示範囲がない）、`is deisotoped`（deisotoping を実装したら戻す）。

### 3.3 `data_hash` と `scan_sha256`

どちらも SHA-256 の小文字 16 進（64 文字）。使い方は、軽い `scan_sha256` で候補を絞り、それに通ったものを `data_hash` で最終確認する。`scan_sha256` が同じで `data_hash` が違えば、同じ測定から作られたが中身の変わったデータ（スペクトルの削除や校正の書き換えなど）。

- **`scan_sha256`**：`AcqData/MSScan.bin` の中身全体。約 0.1 MB なので一瞬で計算できる。スキャン表には全スキャンの RT・TIC・ベースピーク・スペクトルの格納位置が入るので、別の測定と一致することは事実上ない。
- **`data_hash`**：`AcqData/` の `DefaultMassCal.xml`, `MSMassCal.bin`, `MSPeak.bin`, `MSProfile.bin`, `MSScan.bin` を、この順（アルファベット順）に、存在するものだけ流し込む。各ファイルにつき、`name.encode() + b"\0" + size.to_bytes(8, "little")` のあとに中身（1 MiB ずつのチャンクで読む）。
  - `DefaultMassCal.xml` を入れるのは、m/z の計算に使われるため（多項式のどの次数を使うかの `ValueUseFlags`。係数は `MSMassCal.bin` から読む）。普通は直接いじらない限り変わらない。
- **含めないもの**：`*.tags` など後から増えるファイル、Results フォルダ、`.DS_Store`、`desktop.ini`、パス、更新時刻。reader が読む `MSTS.xml`（スキャン数）と `MSScan.xsd`（スキャン表の並び方）も構造の情報なので入れない。
- **計算のタイミング**：`data_hash` は大きなファイル（手元で 850 MB に 0.5 秒。ネットワークドライブではもっとかかる）を読むので、ファイルごとに1回だけ計算して覚えておき、Export のときに進捗を出しながら計算する。
- **検証値**：

  | .d | `scan_sha256` | `data_hash` |
  | --- | --- | --- |
  | `dummy_RP_2min_neg.d` | `e5081b949ae2413040809130c36e917e97576ed1ff7f0522cb4555d02a5cf7b4` | `120744d611b758a1fe085d423e7568176b642d99ef9695ca09de2e51b1cc715c` |
  | `9_P2-8-15_spl1_p0.d` | `8f6687f1d66f9a2d9081fb90c0e2deb727892b1f0a5f0b092a19cc1bcf53a5ec` | `28de1a56a7305d3fc8d12c5bd1718e341e3a24e1d51d6226603f90af1a5387ba` |

### 3.4 `scan_settings`

データには文字列としては書かれておらず、スキャン表に数値の符号（`IonMode`、`IonPolarity`、`ScanType`）として入っている。これを「イオン化法、極性の符号、空白、スキャンの種類」の順につないだ文字列にする（例：`ESI+ Scan`、`ESI- ProductIon`）。

- 名前に置き換えるのは、手元のデータで確かめた符号だけ：`IonMode` 64 = `ESI`（メソッドの Ion Source は Dual AJS ESI）、`ScanType` 1 = `Scan`（MS1）、512 = `ProductIon`（MS2）。ほかの符号は推測せず、`IonMode 32`、`ScanType 256` のように数のまま書く。
- その行の計算に使ったスキャンに複数の組み合わせがあれば（MS level が All で MS1 と MS2 が混ざる場合など）、`, ` でつなぐ。

## 4. 値の書式

- **数値**：`1234.5` の形のみ（桁区切りなし、小数点は `.`、NaN・inf は不可）。書き出しは保存されている値をそのまま全桁で書く（Python の `repr`）。画面の表示桁には丸めない。
- **決まった値**：大文字小文字まで完全一致（`XIC`/`TIC`/`BPC`、`All`/`MS1`/`MS2`、`abs`/`ppm`）。
- **空欄**：§3 で空欄を許す列だけ。値が無いことを表すのは空欄だけ（`-1` や `nan` は使わない）。
- **検証**：Target と同じ規則で行う（adduct と formula の書式、MS2 以外にプリカーサーの値がないこと、ppm が整数であること、など）。

## 5. Import

### 5.1 見出し行と形式の判定

- 列名は大文字小文字まで完全一致で、同じ列は1回だけ。知らない列があればエラー。
- §3.1 のターゲット列はすべて必須（順不同）。§3.2 の列は、あってもなくてもよい（読み飛ばす）。
- 見出しに `adduct` か `trace_type` があれば新形式、`is_TIC` があれば RAPID2 形式（§7）として読む。

### 5.2 エラー

最初の1件で止めず、行番号・列名・理由をまとめて一覧で見せ、1件も取り込まない。

- 行番号は見出し行を 1 とする。空の行は読み飛ばす。欄の数が見出しと違う行もエラー。
- Target の検証で弾かれた行は、列名の代わりに Target のメッセージを出す（例：`line 3: Invalid adduct: '[M-H]' ...`）。
- 一覧は最初の 20 件、残りは件数（Export の知らせと同じ）。

### 5.3 行をターゲットにまとめる

仕様として「`#` が同じ行は、ターゲット列の値もすべて同じ」とする。このアプリが書き出したファイルでは常にそうなる。

| 状況 | 扱い |
| --- | --- |
| `#` が同じで、ターゲット列の値も同じ | 1つのターゲットにまとめる |
| `#` が同じで、値が違う | 警告ダイアログを出し、`#` ごとに「別のターゲットにする」「値1を使う」「値2を使う」…から選ばせる（「すべてに適用」付き。値は最初に出てくる行の行番号で示す） |
| `#` が違って、値が同じ | 別のターゲットのまま残す（Duplicate で複製したターゲットも往復で残る） |

- 「値」はターゲット列（§3.1）のうち `#` 以外のすべて（Note も含む）。値は出てくる順に値1、値2…とする。
- 行の順番が入れ替わっていても、`#` でまとまる。
- 「すべてに適用」は、残りの `#` にも同じ選び方をする：「別のターゲットにする」はそのまま、「値 n を使う」は n 番目の値（値が n 個未満なら最後の値）。ダイアログの Cancel は取り込み全体をやめる。
- 「別のターゲットにする」と、その `#` の値は出てくる順に続き番号になる。
- AI アシスタントと CLI は聞けないので、値が違えば別のターゲットにする。

### 5.4 取り込み

- 取り込むターゲットは `#` の小さい順に並べ、番号は振り直す。
- ターゲットのリストが空でなければ、「置き換える」か「末尾に追加する」かを聞く。どちらの場合も Undo 1回で戻せる。

## 6. 定量値の計算

RAPID2 の `calc_chromatogram_auc` と同じ定義にする。そのうえで、RAPID2 のバグ（§9）と例外の扱いを直す。

### 6.1 使うスキャン

- ターゲットの MS level（`All`/`MS1`/`MS2`）、MS2 ならプリカーサーと CE で選ぶ（画面のクロマトグラムと同じ選び方）。
- **adduct の電荷の符号と同じ極性のスキャンだけを使う**（XIC、TIC、BPC のすべて。§10）。
- RT 窓は `[RT − RT_range, RT + RT_range]`（両端を含む。このアプリの既存のスキャンの選び方に合わせる。RAPID2 は下端を含まない）。
- 画面で RT 窓をファイルごとにしているとき（`Link RT windows` を外しているとき）、ファイルごとの積分区間（そのファイルでターゲットのピークとした区間）が決まっていれば、RT 窓の代わりにその区間を使い、m/z 窓もその区間を決めたときの XIC のものを使う。積分区間は .d フォルダのパスで引く（同じフォルダは2回開けない）。`Link RT windows` を付けているときは、すべてのファイルでターゲットの RT 窓を使う。AI アシスタントの `rapid2_export_targets` も同じ。
- `Link RT windows` を外しているとき、まだピークを探していないターゲットとファイルの組は、書き出しの前に Auto と同じようにピークを探し、その結果を画面にも残す。ターゲットのピークは、見つけたピークのうち頂点がターゲットの RT 窓の中にあり、RT に最も近いもの。窓の中に頂点が無ければ「ピークなし」。
- ピークが無いとしたファイルでは、`N_scans (value used for calculation)`（0）のほかの結果列をすべて空欄にし、§6.4 の知らせに `no peak taken for the target, so no values` と出す。

### 6.2 各スキャンの値

- **XIC**：m/z 窓 `[m/z_btm, m/z_top]` の中にあるプロファイル点の強度の合計（今の XIC と同じ）。
- **TIC / BPC**：スキャン表の TIC / ベースピーク強度。
- **窓の中に点が無いスキャン**は欠測として計算から外す（決定）。「信号が無い」のではなく「その m/z を測っていない」ため。§6.3 の台形則は、欠測の前後のスキャンを直線でつなぐことになる。
  - 起きるのは2つの場合だけ。窓がプロファイル点の間に落ちた場合（窓の幅がデータ点の間隔より狭いとき）と、窓がそのスキャンの測定 m/z 範囲の外にある場合。窓の幅がデータ点の間隔以上なら、窓の中には必ず点が入る。
  - 強度 0 の点が窓の中にある場合は、測った結果が 0 なので、0 のまま扱う。
  - 窓が狭すぎるときは、クロマトグラムの中に警告を出す（§10）。
  - 実データでの確認（`9_P2-8-15_spl1_p0.d`、choline 104.107、92スキャン）：基準（欠けの無い ±3 ppm）の area 18,842 に対し、欠測を外すと ±1 ppm（9スキャン欠け）で 18,919、±0.5 ppm（47スキャン欠け）で 19,152。0 として計算すると、それぞれ 16,489 と 8,751 になる。信号の無い m/z（104.5）では、外してもノイズの値（≈75）のままで、無い信号を作り出すことはない。

### 6.3 定量値

使えるスキャン（欠測を除く）の値 `y` と RT `t` から計算する。

| 列 | 定義 |
| --- | --- |
| `area` | 最初から最後のスキャンまでの台形則の積分。単位は 強度 × min。窓の端までは延長しない |
| `RT_btm/RT_top (value used for calculation)` | 積分に使った最初と最後のスキャンの RT |
| `baseline_height` | `y` の最小値 |
| `area (baseline adjusted)` | `area − baseline_height × (最後の RT − 最初の RT)`（最小値の高さに平らなベースラインを引く） |
| `height` | `y` の最大値 |
| `RT peaktop` | `y` が最大のスキャンの RT。`height` が 0 なら空欄 |
| `mz peaktop` | 使ったスキャンの平均スペクトルで、m/z 窓の中の最大の m/z（TIC/BPC は全範囲）。最大値が 0 なら空欄 |
| `area (deconvolved)` | ピーク検出器（`services/peak_deconvolution.py`、`training/peak_detector`）が、重なったピークを分けて求めた、そのピークの形の面積。単位は 強度 × min。ベースラインと隣のピークは含まない。RT 窓の点の積分ではない |
| `area (deconvolved) sigma` | `area (deconvolved)` の誤差の 68% が入る幅（合成データで補正したもの） |
| `area (deconvolved) 95% interval` | 同じく 95% が入る幅（±）。誤差の分布の裾が重いので、sigma の 2 倍より広い |

- 使えるスキャンが2未満（RT 幅 0、極性が合わない、など）のときは、`N_scans (value used for calculation)`（0 か 1）のほかの結果列をすべて空欄にする。
- `mz peaktop` の平均スペクトルは、XIC では m/z 窓の中だけで作る（全 m/z で作るのと同じ値で、約 20 倍速い）。格子は、使ったスキャンの RT の真ん中に最も近いスキャンのデータ点。
- area は窓の中の点の合計から計算するので、m/z 窓の幅で値が変わる（RAPID2 と同じ定義。同じターゲットをファイル間で比べる用途なので問題ない）。
- `area (deconvolved)` とその不確かさは、そのファイルの積分区間が、ピーク検出器の見つけたピーク（ターゲットに選ばれたもの）のときだけ書く。ほかの検出器、手で決めた区間、ピークが選ばれていないときは空欄。区間の点の値（`area` など）は、そのピークの範囲（形が頂上の 5% まで下がるところ）で計算する。

### 6.4 Export の操作と警告

- 保存先の既定は、最後に開いたフォルダに、そのフォルダ名 + `.rpd.csv`。`.rpd.csv` で終わらない名前は補い、補った名前のファイルがすでにあれば置き換えてよいかを聞く。
- ハッシュの計算（読むバイト数）と面積の計算（ターゲット × ファイル）の進捗を出し、途中で止められる。止めたときは何も書かない。
- 書き終えたら、結果が空欄になった行と、欠測のスキャンを外した行を、ターゲットとファイルの一覧で知らせる（最初の 20 件、残りは件数）。

## 7. 古い RAPID2 形式の読み込み

RAPID2 の Export Targets が書き出したファイル（タブ区切り、拡張子 `.csv`）を、Excel を通していない前提で読む。

- **ファイルの形**：先頭列は見出しのない行番号。真偽値は `True` / `False`。同じ名前の列が2回出てくることがある。
- **読む列**：RAPID2 の Load Targets と同じく、`compound_name`, `formula`, `is_TIC`, `m/z`, `m/z_range`, `RT`, `RT_range` の7列。ほかの列（`file_path`、`area`、`view_range_*` など）は読まない。`view_range_*` の Python のリスト文字列は、決して評価しない（RAPID2 は `eval()` していた）。
- **まとめ方**：先頭列は行番号で1行ごとに違うので使わない。RAPID2 と同じく、7列の値（文字列）が同じ行をまとめる。番号は最初に出てくる順に 1, 2, …。値は、まとめた行の最初の行から読む。
- **数値**：RAPID2 の書いた形（pandas）なので、§4 より緩く、Python の `float` で読める有限の値なら受け付ける。

| RAPID2 | このアプリ |
| --- | --- |
| `compound_name` | name。末尾が `[M+Cl]-` などの adduct 書式なら、その部分を adduct として切り出す |
| `formula`（イオン式） | adduct が分かれば、イオン式から adduct の分を引いて中性の式にする（`[2M+Na]+` は引いてから2で割る）。分からなければ電荷だけ外し、adduct は `[M]+` / `[M]-`（2価なら `[M]2+`）。名前の adduct でイオン式が作れない（引くと負や割り切れない数になる、電荷が違う）ときも同じで、名前はそのままにする。式は Hill の順（C、H、残りはアルファベット順。C が無ければすべてアルファベット順。同位体 `[13C]` はその元素の直後）で書く |
| `is_TIC` | `True` → TIC、`False` → XIC |
| `m/z` | mz。**ファイルの値をそのまま使う**。TIC の `-1` は既定値に置き換える |
| `m/z_range` | mz_tolerance（単位は abs）。TIC の `-1` は既定値に置き換える |
| `RT`, `RT_range` | rt, rt_tolerance |
| なし | MS level は MS1 |

- RAPID2 の m/z は電子の質量を入れずに計算されている（例：PC 30:0 `[M+Cl]-` は RAPID2 で 740.4997、このアプリでは 740.5003）。ファイルの値をそのまま使うので、formula から計算した m/z とは 0.00055 ずれて、不一致の色が付くことがある。
- 名前に adduct が無く、式が `C36H72NO8PH+` の場合は「`C36H73NO8P` + `[M]+`」になる（化学的には正しいが `[M+H]+` にはならない）。

## 8. 決めたこと（Import の実装で）

未決事項はすべて決まった。

1. **RAPID2 形式で formula が空のターゲットの adduct**：名前の末尾に adduct があればそれ。無ければ、その行の `scan_settings` の極性（`ESI+ QuadrupoleTimeOfFlight SCAN` などの、各スキャンの種類のイオン化法の後の `+` / `-`。すべて同じ符号のときだけ）から `[M+H]+` / `[M-H]-`。どちらも分からなければ、パネルの既定の `[M+H]+`。
2. **File メニューの名前**：「Load Targets」のままにする（変更を最小にするため）。

## 9. RAPID2 の面積計算のバグ（このアプリでは直す）

RAPID2 の `database.calc_chromatogram_auc` と `rpd_calc.extract_chromatogram_core_float64int32` で見つかったもの。

1. **profile データで NaN が広がる。** m/z 窓の中に点が無いスキャンは NaN になる（これが RAPID2 で「クロマトグラムが途中で切れる」原因）。profile データ側では NaN を処理していないので、1スキャン欠けただけで `area`・`baseline_height`・`area (baseline adjusted)` がすべて NaN になる。さらに `np.argmax` は NaN を最大とみなすので、`height` が NaN になり、`RT peaktop` に最初に欠けたスキャンの RT が入る。v0.2.7 の「空のデータは 0 とみなす」修正は、centroid 側にしか入っていない。
2. **centroid データ側は NaN を 0 にしている。** そのため1スキャン欠けると `baseline_height` が 0 になり、`area (baseline adjusted)` が `area` と同じになる（ベースラインが引かれない）。
3. **信号がまったく無いとき**、`height` が 0 なのに、`RT peaktop` に窓の最初のスキャンの RT が入る。
4. **RT 窓の端の扱い**が「下端を含まず上端を含む」で、このアプリ（両端を含む）と違う。
5. **同じ名前の列**（`RT_btm/RT_top (value used for calculation)`）が2回書き出される。

このアプリの今の抽出では、欠けたスキャンは NaN ではなく 0 になる（1は起きないが、2と3は起きる）。実データでも、±1 ppm で `baseline_height` が 0 に、±0 で `RT peaktop` が意味のない値になった。

## 10. あわせて必要な変更（ファイル形式の外）

- **極性での絞り込み**（クロマトグラム・スペクトル・Precursor の候補一覧に実装済み。面積の計算は Export と一緒に）：adduct の電荷の符号でスキャンを選ぶ。スキャンの極性はスキャン表の `IonPolarity`（0 = 正、1 = 負）で、reader の `polarity_list`（+1 / −1）として持つ。
  - 使う adduct は、Adduct 欄に入力中のもの。入力の途中でも、読める形になった時点（最後の符号を打った瞬間）で切り替える。選択中のターゲットでも確定前の入力で切り替え、欄が空ならターゲットの adduct を使う。ドラフトの Adduct 欄が空のときは絞り込まない（まだ何も指定していないため。負イオンのデータを開いただけで、既定の `[M+H]+` のせいで何も表示されない、ということを避ける）。
  - 切り替えても使うスキャンが変わらないファイル（片方の極性だけのファイルで、その極性にした場合）は描き直さない。合わない極性で空にしたプロットは直前の結果を覚えておき、戻したときに設定が同じなら取り直さずに描く。1ファイルの切り替えは 105–145 ms から 11 ms 以下になった。hide にしないのは、隠したデータが Y 範囲の共有や「全範囲を表示」の計算に紛れ込むため。
  - 極性が合わないファイルのトレースは空にし、クロマトグラムの中に赤字で「No positive scans in this file, for the adduct's charge」などと表示する。
- **欠測スキャンの表示**（実装済み）：XIC で窓の中に点が無いスキャン（§6.2）は線から外し、前後の測ったスキャンを破線でつなぐ。破線は §6.2 の積分と同じ線になる。破線の区間だけを別の線として描くので、描画の負担は欠測の数に比例する分しか増えない。Y 範囲は測った点だけから決める。窓が測定 m/z 範囲の外にあるスキャンがあれば「m/z window beyond the scanned m/z range in …」と警告する。
- **m/z の窓が狭すぎるときの警告**（実装済み）：XIC で、窓がプロファイル点の間に落ちて窓の中に点が無いスキャンがあれば、クロマトグラムの中に赤字で「m/z window narrower than the data spacing (7.7 ppm): 9/92 scans have no point in it」などと表示する。
  - 判定は ppm の閾値ではなく、スキャンごとの校正から求めたデータ点の位置で行う（reader の `mz_window_gaps`）。m/z が大きいほど点がまばらになることも、装置の設定の違いも反映される。窓が測定 m/z 範囲の外にあるだけのスキャンは数えない。
  - 速さ：すべてのスキャンの時間軸が同じなら、窓が1つ目のスキャンの点の間隔より 1.1 倍以上広いときは、そこで判定を打ち切る（0.1 ms）。狭いときだけ全スキャンを調べる（598スキャンで約 30 ms）。
- **adduct の入力欄**（実装済み）：書けない adduct は、入力の途中でもその場で背景を赤くする（空欄は既定の adduct なので赤くしない）。エラーの表示は、赤い枠（スタイルシートで枠を描き替えるので、欄の高さが変わっていた）をやめ、m/z が formula と合わないときと同じ背景の赤にした（ほかの欄と検索欄も同じ）。
- **adduct の書式の修正**（実装済み。`models/chemistry.py`）：
  - 電荷 0（`[M+2H]0+`）を弾く。以前は Target の検証を通り、m/z の計算で ZeroDivisionError になっていた。
  - 0倍・0個（`[0M+H]+`、`[M+0Na+H]+`）を弾く。
  - 溶媒の略号に対応した：ACN (C2H3N)、IsoProp (C3H8O)、DMSO (C2H6OS)、FA (CH2O2)、Hac (C2H4O2)、TFA (C2HF3O2)（Fiehn lab の表、Skyline、MS-DIAL で使われる）。略号は組成式の解析より前に置き換える（`Hac` が、H + Ac〈アクチニウム〉と解釈されないように）。なお、Fiehn の表の IsoProp の2行は電子1個分ずれている（こちらの計算が正しい）。
  - Targets パネルの Adduct の横に、記法を説明する info ボタンを置いた。
- **adduct の記法**：今の書式は IUPAC 2013 勧告の形（`[M+H]+`、多価は `[M+nH]n+`）と一致している。主な 16 種の m/z は、Fiehn の表と 0.02 ppm 以内で一致した。
