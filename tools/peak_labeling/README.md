# ピークの正解付けツール

ピーク検出モデルの評価用に、実データの XIC のピークトップへ正解を付けるためのツール。アプリ本体（`src/RAPID2_Agilent`）とは別物で、本体の関数を流用するが、本体からは使わない。パッケージにも入らない。

## 1. XIC を書き出す

```sh
python tools/peak_labeling/extract_xics.py RUN1.d RUN2.d ... --out xics.npz \
    [--targets targets.rpd.csv] [--spots 15] [--random 5] [--ppm 10] [--seed 0] [--keep-calibration]
```

各ファイルの、測定全体の XIC を書き出す。

- `--targets`：`.rpd.csv`（または RAPID2 形式）のターゲット。アプリと同じ選び方（MS レベル、極性、m/z 窓）でトレースする。
- `--spots`：m/z-RT マップで強度の高い位置の m/z。±`--ppm` の窓で、MS1 のスキャンから作る。
- `--random`：ランダムな m/z。種類を広げ、ピークのないトレースを入れるため。
- 質量キャリブレーションが前後のスキャンから跳んだスキャン（m/z 700 か 1200 で、前後 4 スキャンずつの中央値から 10 ppm 超）は、前後の跳んでいないスキャンの値（coeff と base）を RT で補間して直してから書き出す（`calibration.py`）。2026 年の一部のランで起きる装置側の問題で、そのスキャンだけ XIC が数 % に落ち込むため。直すのはこのツールが読み込んだデータのメモリ上だけで、アプリ本体は保存されたまま読む。`--keep-calibration` で直さない。直したスキャンは、データセットの `runs` にランごとに残る。

## 2. 正解を付ける

```sh
python tools/peak_labeling/label_peaks.py xics.npz [--labels xics.labels.json]
```

候補の頂点を出すので、良いものを選ぶ。

- 候補：Kensert らの CNN が出す頂点（確率 0.3 以上、数字はその確率）と、簡易版（scipy）の頂点のうち、ノイズの 5 倍以上目立つもの（「scipy」と表示）。
- 候補をクリック：採用（緑の▲）→ 却下（赤の×）→ 保留（橙の◆）→ 未決（灰色の○）と切り替わる。
- 保留：ピークとも、ピークでないとも言えない頂点。採点しない（そこを検出しても、しなくても数えない）。
- Shift + クリック：そこを頂点にして採用する。近くの 3 スキャン以内でいちばん高い点に合わせ、候補がちょうどそこにあればそれを採用、なければ頂点を足す（青の▲）。そのとき近くにある、頂点からずれた候補は却下、足した頂点は消える（頂点の位置を直すのにも使う）。足した頂点をクリックすると保留（橙の◆、青の縁）に、もう一度で消える。
- A：確率 0.9 以上の未決の候補をまとめて採用。
- Done（Enter）：そのトレースを全体まで見終わったとして確定する。未決の候補は却下になり、次の未確定のトレースへ移る。
- N / P：次・前のトレースへ。
- Ctrl + Z（Mac では ⌘ + Z も）：直前の変更を戻す（200 回まで。別のトレースの変更なら、そのトレースに移って戻す）。
- Of no use：使えないトレース（壊れている、など）の印。Note は自由なメモ。
- Help：操作と付け方の決まりの一覧（開いたまま作業できる）。

ラベルは変更のたびに保存される（既定ではデータセットの横の `xics.labels.json`）。候補はトレースを初めて開いたときに計算して保存するので、あとで検出の方法が変わっても変わらない。

## 決まりごと

- ターゲットかどうかに関係なく、トレースの中のピークはすべて付ける（blank の未知のピークも）。
- 「Done」で確定したトレースの、何も付いていない部分は「ピークなし」とみなす。全体を見終わってから確定する。
- 重なったピーク、割れたピークは、頂点をそれぞれ付ける。シミュレータの決まり（training/peak_detector/SPEC.md §2）に合わせて：
  - 頂点が2つあり、間に谷が見える → 2つとも採用。
  - 自分の頂点を持たない肩、ノイズ程度の谷 → 大きい方を採用、小さい方を保留。
  - 頂点が1つにまとまっている → 1つ。
- ノイズからはっきり出ていない（S/N が 2〜5 くらい）の小さな山は保留。
- 保持されずに出たピーク（void 付近）も、ピークなので付ける。
- 1スキャンだけの落ち込みや飛び出しはピークでも、ピークの割れでもない（キャリブレーションの跳びなど。data/peak_eval/README.md）。

## ラベルの形式

```json
{"dataset": "...", "traces": {"0000": {
    "candidates": [{"rt": 3.29, "source": "kensert", "confidence": 1.0, "state": "taken"}],
    "added": [3.05], "added_unsure": [], "done": true, "unusable": false, "note": ""}}}
```

`state` は `taken`（採用）、`left`（却下）、`unsure`（保留）、`undecided`（未決）。正解の頂点は、`taken` の候補と `added` を合わせたもの。保留の頂点は、`unsure` の候補と `added_unsure`（保留の前に作ったラベルには無い）。
